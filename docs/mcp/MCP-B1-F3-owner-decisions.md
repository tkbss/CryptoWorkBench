# MCP-B1-F3 owner decisions

These decisions govern the supported desktop workspace and its focused final review. Severity below is the independent review's original classification. [F2-R1 findings](MCP-B1-F2-R1-independent-rereview.md)

| Decision | Finding and disposition | Supported contract, residual risk and reopening condition |
|---|---|---|
| **OD-F3-01** | **F2R-01 · High · Accepted architectural boundary** | One editor-owning WorkbenchAutomationService supplies one bridge and one global EditorCoordinator per workspace. Future tabs share that owner and retain separate registrations and native document histories. Desktop DI registers the same Shared object both concretely and through the automation interface. The editor view attaches through its injected VM and service, and the MCP transport receives the service interface. Independently constructing two owners and binding distinct controls over the same TextDocument can still share an undo stack. This is unsupported. Reopen if a supported composition or tab can bind a second owner, or if shared-buffer views are introduced. Multiple authorized interpreter callers continue to share interpreter admission. |
| **OD-F3-02** | **F2R-02 · High · Supported host callbacks assessed, foreign raw-event exception risk accepted** | For a real native finish, the early document guard returns normally. Completion refresh and host caret presentation run under controlled observation, which contains callback exceptions and checks the drain in its finally. The synthetic finish produced by rejecting a native BeginUpdate deliberately stops dispatch before unmatched native subscribers run. An arbitrary earlier subscriber that throws directly from the raw document's UpdateFinished multicast can still prevent delivery to the drain listener. Reopen if a supported host-installed listener can let an exception escape a genuine finish, or if the native dispatch order changes. No general raw-event dispatcher is part of B1. |
| **OD-F3-03** | **F2R-11 · Low · Accepted native-semantic deviation** | One logical whole-line Cut has one Undo/Redo group, including for disjoint writable segments. The clipboard contains the original normalized whole line. Only the approved segments are removed. This intentionally differs from the pinned editor's individual whole-line removals. Reopen if the permitted write set, clipboard text, one-step history or later editor admission changes. |
| **OD-F3-04** | **F2R-12 · Low · UI feedback deferred** | Replace All may fail closed on an unversioned custom protection provider. No product implementation installs such a provider. The enabled command can therefore be a silent no-op in a custom integration. Ordinary search uses the native unrestricted policy. Reopen availability or rejection feedback when an application-supplied custom policy or a user-facing requirement needs it. Keep coherent authorization in force. |
| **OD-F3-05** | **Scope and stopping rule** | The next review covers F2R-03, F2R-04, F2R-05 and F2R-06 (High), F2R-07 and F2R-08 (Medium), the two boundary assessments above, the F2R-09 and F2R-10 dispositions (Low), and meaningful supported-path regressions. A demonstrated supported Critical or High issue blocks readiness. Accepted raw-library behavior, documented native differences and deferred UI feedback do not trigger an unrestricted audit. Reopen a decision when its stated supported precondition changes or a supported product path violates it. |

### Composition and subscription evidence

The application registers the service and interface against the same instance. The VM's default constructor path also uses Shared. The view's visual attachment, selection and detachment use the VM's original registration. Fresh interpreter admission still consults the shared queue. [Application DI](../../CryptoWorkBenchAvalonia/App.axaml.cs) · [Editor view lifecycle](../../CryptoWorkBenchAvalonia/Views/CryptoScriptEditView.axaml.cs) · [Editor registration and coordinator](../../CryptoWorkBenchAvalonia/Services/Automation/WorkbenchEditorOperations.cs) · [MCP transport injection](../../CryptoWorkBench.Mcp/StatusTransport.cs)

WorkbenchTextEditor installs its native guard during document coercion, before the host attaches the view and completion controller. InfoCompletionController subscribes on the current document and removes subscriptions on replacement or disposal. BeginDrain later subscribes to the original open group. Native caret notification can also reach view and completion listeners, both wrapped by the host. The focused fixture induces an exception while the actual completion list is being refreshed, waits for the certificate without stimulating the coordinator, resumes and types. The independent foreign-handler reproduction remains available in its original evidence directory.
