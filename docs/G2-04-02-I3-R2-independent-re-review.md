## R1-H01 · Rendering, input and value integrity

The grid's Value template and selected Value detail use a OneWay converter before setting `TextBlock.Text`. Values up to 128 UTF-16 units pass through. For longer values, the control receives a prefix plus an ellipsis. When the boundary crosses a valid surrogate pair, the prefix retreats one unit. The original row and declaration retain the complete value. The Inspector independently resolves the bound snapshot source, copies it through the existing clipboard action and pages its full-text control in chunks of 4,096 units. Moving selection through the attached grid still updates the shared model. Detach/reattach suppresses the temporary reset caused by Avalonia. [Variables binding](../CryptoWorkBenchAvalonia/Shell/DockVariablesView.cs#L94) · [Inspector full text](../CryptoWorkBenchAvalonia/Views/DockVariableInspectorView.cs#L96) · [Snapshot copy](../CryptoWorkBenchAvalonia/ViewModels/VariableInspectorViewModel.cs#L153)

A separate R2 native probe read both actual controls for a short string containing whitespace, CRLF and a surrogate pair, an exact 128-unit string, and three 129-unit boundary cases. Both controls preserved the short values and produced the expected prefix without splitting a pair. Selection changes, the original row/declaration values and final deselection were checked. ## New findings affecting owner acceptance

### R2-H01 · High · A long valid identifier stalls both Variables and Inspector

**Location.** The Identifier column receives the entire identifier before applying visual ellipsis. The selected Identifier detail receives the entire string with wrapping. Independently, the Inspector builds its wrapped heading from the full snapshot identifier. The lexer accepts alphanumeric identifiers of this length. [Grid and detail](../CryptoWorkBenchAvalonia/Shell/DockVariablesView.cs#L44) · [Inspector heading](../CryptoWorkBenchAvalonia/Views/DockVariableInspectorView.cs#L110) · [Title source](../CryptoWorkBenchAvalonia/ViewModels/VariableInspectorViewModel.cs#L29) · [Lexer](../CryptoScript/Antlr/CryptoLexer.g4#L19)

**Reproduction.** Use a name consisting of `v` followed by 65,535 `a` characters and a short value. R2 independently submitted such a `VAR` declaration through the GUI parser and verified the full identifier in the published row. In a fresh process, publish an equivalent ordinary string declaration in the three-column layout, then select that row. The performance fixture used a short literal value so the identifier is the long field. Repeat with only the Inspector visible. [Parser acceptance](../artifacts/test-results/g2-04-i3-r2/more/parse-parse.log) · [First visible reproduction](../artifacts/test-results/g2-04-i3-r2/remaining/identifier-65536.log) · [Repeat and hidden control](../artifacts/test-results/g2-04-i3-r2/name-check/analysis.json)

**Expected and observed.** The user should be able to select a valid declaration, navigate its Inspector and retain its exact identity. In two independent three-column processes the page did not become usable before the eight-second guard. No queued input callback was served during either measured interval. The oldest outstanding request had waited at least 8,138 and 8,094 ms, respectively, at the last recorded post. At 4,096 identifier units, the repeat took 881 ms to become usable and delayed input by up to 795 ms. With Variables hidden, the 65,536-unit case still took 2,687 ms and delayed input by 2,633 ms. This localizes the issue beyond the Variables pane; the exact rendering cost of each individual control has not been profiled.

**Acceptance impact.** This is a reproducible loss of interaction on a script-valid declaration. Its rarity does not remove its effect on a user opening the Inspector. The routes predate F1, and the short-value evidence for the original R1-H01 case remains valid. An owner-acceptance recommendation needs a counterprobe covering both identifier presentations while preserving full identifier identity and copy semantics.

## R1-M01 · Persistence, comparison and durability

`Load` prefers v2. A missing v2 permits historical validation and create-only migration. An access or IO failure protects the fallback, as does a failed first installation without a winner. Invalid JSON follows the established default-repair policy. The shell captures the normal dock projection with fixed comparison bounds, preserving ordered groups, active children, proportions, floating hosts and closed tools. At shutdown it compares that projection **before** BeginShutdown, drain or host teardown. Only an assigned closing snapshot can be written at actual `Closed`. Normal focus mode captures its saved normal tree. **Comparison and durability limits.** Under protected fallback, a main-window-only geometry change or a deliberate reset to exactly the same fallback tree leaves the protected file intact. That is the documented F1 policy, including when the operator changed main-window geometry intentionally. A different ordered tree or structural container identity can compare unequal even if the layouts look similar; no false save occurred in the tested undo sequence. Serialization/capture failure cannot assign a partially built closing snapshot. Save validates, flushes and rereads a same-directory temporary file, then uses Move or Replace. Unexpected failures outside the recoverable exception filter can still surface as application/shutdown failures. R2 did not simulate process termination inside the OS replacement, power loss or conflicting ordinary edits by two already-running writers. The tested race protects first installation; it does not establish general multi-writer conflict resolution.
