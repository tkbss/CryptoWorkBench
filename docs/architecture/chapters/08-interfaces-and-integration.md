## 8.1 Local Automation in the Desktop

The user pairs an external MCP client with the editor already open in CryptoWorkBench. The [process view](../diagrams/02-container-overview.mmd) follows two invocations of the desktop executable. Normal startup attaches a consent handler to the shell. Starting with `--mcp-stdio` selects a transport proxy before Avalonia starts. The client exchanges MCP messages with the proxy over standard input and output. The proxy forwards tool calls over TLS to the running desktop. [E02](../evidence/mcp-a1.md#e02), [E03](../evidence/mcp-a1.md#e03), [E05](../evidence/mcp-a1.md#e05)

The production pairing control is visible on Windows. Consent opens the loopback endpoint. Both the standard shell and the optional dock shell use the same service. The desktop process owns the live editor, callback destinations, jobs and shared CryptoScript variable dictionary. Two HTTP calls can therefore observe effects in the same workspace. Starting a proxy or creating a runner allocates no private interpreter state. [E02](../evidence/mcp-a1.md#e02), [E03](../evidence/mcp-a1.md#e03), [E12](../evidence/mcp-a1.md#e12), [E15](../evidence/mcp-a1.md#e15)

## 8.2 Contracts and Composition

The [project graph](../diagrams/01-project-references.mmd) shows direct build references. CryptoWorkBenchAvalonia.Desktop references CryptoWorkBenchAvalonia and CryptoWorkBench.Mcp. The GUI references CryptoScript and CryptoWorkBench.Automation.Abstractions. Mcp references the abstractions. Both Core and the contract library are independent of MCP and Avalonia. At runtime the adapter calls an implementation in the GUI through `IWorkbenchAutomationV2`. [E01](../evidence/mcp-a1.md#e01), [E02](../evidence/mcp-a1.md#e02), [E06](../evidence/mcp-a1.md#e06), [E07](../evidence/mcp-a1.md#e07)

Prism/DryIoc registers `WorkbenchAutomationService.Shared` as the concrete service and under both automation interfaces. Desktop startup injects the pairing hook. On consent, the listener builds its own ASP.NET Core host with the existing service and a delegate that resolves the original caller. The proxy hosts its own SDK server. Its cached tool catalog carries schemas and annotations, while authority and job history stay in the original desktop. [E02](../evidence/mcp-a1.md#e02), [E03](../evidence/mcp-a1.md#e03), [E04](../evidence/mcp-a1.md#e04), [E05](../evidence/mcp-a1.md#e05), [E06](../evidence/mcp-a1.md#e06)

The [component view](../diagrams/08-automation-components.mmd) separates control access from interpreter admission. The dispatcher owns editor registration and mutation. The registry serializes job admission and result publication under a lock. A process-wide, non-waiting host reservation excludes competing operations. Core enforces its own interpreter ownership, including callback and state-access rules. Host contracts carry detached data across these boundaries. ## 8.3 Pairing, Transport and Trust

After consent, the desktop activates a one-use epoch, generates a 32-byte random bearer token and issues a `local-codex` caller with eight grants. Kestrel serves `https://127.0.0.1:51837/mcp` with a session-specific leaf certificate and an eight-hour default lifetime. Port collision ends startup. The dialog shows the endpoint, executable, token, SHA-256 leaf fingerprint and expiry. A fresh Workbench process requires fresh pairing. [E03](../evidence/mcp-a1.md#e03), [E04](../evidence/mcp-a1.md#e04), [E08](../evidence/mcp-a1.md#e08)

The proxy reads the pin and token from its environment and clears the inherited token entry. It requires a valid leaf with the configured fingerprint before sending HTTP credentials. Redirects, cookies and network proxies are disabled. The listener checks the exact Host and raw target, rejects Origin headers, and checks the bearer on each request, including expiry and revocation. Only the public CA is exported as PEM. Disposal releases the private identity and retries public-file cleanup. A direct HTTPS client is responsible for its own peer checks. Local editor text or approved output can contain test keys, and approved scripts run with desktop filesystem permissions. [E03](../evidence/mcp-a1.md#e03), [E04](../evidence/mcp-a1.md#e04), [E05](../evidence/mcp-a1.md#e05), [E13](../evidence/mcp-a1.md#e13), [E30](../evidence/mcp-a1.md#e30)

During [authenticated discovery](../diagrams/08-pairing.mmd), the proxy initializes an upstream SDK client and lists tools before advertising them on STDIO. The desktop uses SDK 2.3.0, stateless Streamable HTTP and no legacy SSE listener. Middleware bounds the request body, validates routing and duplicate fields and binds a single-use receipt to the original POST, request ID, parameters and catalog. Only then can a tool resolve the host-issued caller and validate its contract. Protocol version negotiation is distinct from application contract version 2. [E01](../evidence/mcp-a1.md#e01), [E05](../evidence/mcp-a1.md#e05), [E06](../evidence/mcp-a1.md#e06), [E07](../evidence/mcp-a1.md#e07), [E09](../evidence/mcp-a1.md#e09), [E22](../evidence/mcp-a1.md#e22)

Host/target rejection yields HTTP 403, invalid bearer authorization 401. Malformed envelopes and arguments use JSON-RPC errors. A valid call can instead return a structured domain error such as `RevisionConflict` or a failed execution outcome. The STDIO filter normalizes protocol error text and strips error data. The historical B4 review qualifies two guarantees. Some direct-HTTPS method errors can echo caller input, and SDK continuations can issue an additional dispatch despite the proxy having no application retry loop. Refresh uncertain mutations. A lost response alone does not justify replay. [E04](../evidence/mcp-a1.md#e04), [E05](../evidence/mcp-a1.md#e05), [E06](../evidence/mcp-a1.md#e06), [E09](../evidence/mcp-a1.md#e09), [E30](../evidence/mcp-a1.md#e30)

## 8.4 Editor Identity and Control

An editor ID identifies a registered document. Replacing the document changes its ID. Its revision follows observed text versions. Workspace generation invalidates local intents across ownership or registration transitions. The state version tracks published interpreter effects. These counters answer different questions: a script can be unchanged while its variables have changed. Reads address a live registration by ID and never silently follow a successor. [E10](../evidence/mcp-a1.md#e10), [E11](../evidence/mcp-a1.md#e11), [E13](../evidence/mcp-a1.md#e13), [E17](../evidence/mcp-a1.md#e17)

An acquisition ID identifies an attempt for a particular instance, epoch, principal, editor and expected revision. The process ledger recognizes an exact replay and rejects conflicting reuse. On admission the coordinator grants exclusive control of one registration. The initial lease lasts ten minutes. Renewal checks the expected lease version and starts a new ten-minute interval. A monotonic Windows clock determines the deadline. A dispatcher timer wakes the service, and operations recheck the deadline even if the timer is late. [E11](../evidence/mcp-a1.md#e11), [E12](../evidence/mcp-a1.md#e12), [E23](../evidence/mcp-a1.md#e23)

The [control lifecycle](../diagrams/08-editor-control.mmd) has five coordinator phases: `Unavailable`, `Gui`, `Mcp`, `Releasing` and `Faulted`. The public DTO also defines `Acquiring`, which the coordinator never publishes. Release and expiry fence new lease work and cancel work tied to it. Returning the original drain certificate requires pending producers, native edits and callbacks to settle. Until then the GUI can display the document while writes remain blocked. The internal `ReclaimEditor()` ends a lease. Production exposes session-wide Disconnect Codex, which also revokes credentials and result access. See [Chapter 9](09-data-flows-and-execution-sequences.md). [E03](../evidence/mcp-a1.md#e03), [E07](../evidence/mcp-a1.md#e07), [E10](../evidence/mcp-a1.md#e10), [E11](../evidence/mcp-a1.md#e11), [E12](../evidence/mcp-a1.md#e12), [E21](../evidence/mcp-a1.md#e21), [E23](../evidence/mcp-a1.md#e23)

## 8.5 Operations and Visible Data

**Observe.** `workbench_get_status` returns the instance, control phase and state version. Only the owner sees its lease details. `workbench_get_editor` returns bounded, revision-bound editor text under the editor-read grant. `workbench_get_variables` returns a detached metadata snapshot, with identifiers, selected type/key attributes and a stale flag. It omits raw values, parameters and key bytes. [E06](../evidence/mcp-a1.md#e06), [E07](../evidence/mcp-a1.md#e07), [E13](../evidence/mcp-a1.md#e13), [E17](../evidence/mcp-a1.md#e17), [E18](../evidence/mcp-a1.md#e18)

**Control.** `workbench_acquire_editor`, `workbench_renew_editor` and `workbench_release_editor` operate on the owner binding. Acquisition and renewal require control and write grants. Release requires control. The service checks the original issued credential object and active epoch. Possessing a lease ID alone grants no access. [E06](../evidence/mcp-a1.md#e06), [E08](../evidence/mcp-a1.md#e08), [E12](../evidence/mcp-a1.md#e12)

**Change and run.** `workbench_update_editor` can insert, append or replace text at a checked revision. `workbench_execute_editor` requests a run of a concrete editor snapshot with an expected state version and execution ID. An edit requires `editor.write`, `editor.control` and a live lease binding. A new run requires `execution.run`, `editor.control` and that binding. Requesting `IncludeText` also requires `output.read` at admission. Each newly admitted run needs local approval. Output defaults to metadata. On disclosure the service filters Print/Info text again using the original request, local approval and the current output-read grant. [E06](../evidence/mcp-a1.md#e06), [E13](../evidence/mcp-a1.md#e13), [E17](../evidence/mcp-a1.md#e17), [E23](../evidence/mcp-a1.md#e23)

**Follow an admitted job.** `workbench_get_execution` and `workbench_get_diagnostics` expose caller-filtered results, diagnostic codes, locations and fixed messages. `workbench_cancel_execution` uses the same execution-read grant and job ownership. Its receipt reports acceptance of the request. Historical lookup is bounded by revocation, retention and eviction. [E06](../evidence/mcp-a1.md#e06), [E13](../evidence/mcp-a1.md#e13), [E14](../evidence/mcp-a1.md#e14), [E17](../evidence/mcp-a1.md#e17)

GUI save binds an editor snapshot and workspace generation to a selected file target. It rechecks identity and overwrite approval before committing the captured text. A file effect can survive a later failure. A live inspector read reserves host admission, captures values and rechecks selection on the dispatcher. Copies of detached historical data can outlive a lease transition. The eleven-tool catalog exposes neither of these local capabilities, nor separate syntax validation, arbitrary-text execution, direct variable writes or a password-response tool. Parsing and file operations may occur inside an approved script. [E06](../evidence/mcp-a1.md#e06), [E16](../evidence/mcp-a1.md#e16), [E20](../evidence/mcp-a1.md#e20), [E25](../evidence/mcp-a1.md#e25)
